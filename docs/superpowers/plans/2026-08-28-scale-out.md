# Scale-out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Many concurrent live drafts on one Railway service, bounded memory, mutable state in Supabase Postgres, edge caching via Cloudflare, and a faster frontend.

**Architecture:** `api/live.py` moves from one `state` dict to a registry of `LiveSession` objects keyed by an `espn_live` cookie; heavy builds run in a process pool; the board build reads `weekly` once with a column projection and no longer keys on the drafted set. Custody, billing and the live session record gain a Postgres backend selected by `SUPABASE_DB_URL`, DuckDB remaining the default for tests and local use. Static assets and public GETs carry cache headers Cloudflare honours.

**Tech Stack:** Python 3.10, FastAPI/Starlette, DuckDB, pandas, psycopg 3 (+ psycopg_pool), React 18 + Vite, Cloudflare Free.

**Spec:** `docs/superpowers/specs/2026-08-28-scale-out-design.md`

## Global Constraints

- No `SUPABASE_DB_URL` in the environment means every store behaves exactly as today (DuckDB files). The test suite never needs Postgres.
- `LIVE_BUILD_WORKERS` unset or `0` means builds run inline in the request thread (tests monkeypatch `api.live.build_session`; a child process cannot see that).
- Existing tests stay green: `.venv/bin/pytest -q` (note: `make up` running causes ~47 unrelated `test_live_api` failures from the DuckDB lock; stop it first).
- Commit per task to `main` with explicit `git add <paths>`; never `git add -A` (`data/` symlinks, patches in the tree).
- Nothing in this plan deploys. The owner runs `railway up`.
- Public-facing prose (docs, comments, commit messages) is normal prose.

```python
# pipeline/pgstore.py
"""One Postgres pool for every store that has a Postgres backend.

Selected by SUPABASE_DB_URL. Absent, `enabled()` is False and every store
keeps its DuckDB file, so tests and a laptop never need a network.
"""
from __future__ import annotations

import os
import threading

DSN_ENV = "SUPABASE_DB_URL"

_lock = threading.Lock()
_pool = None


class StoreError(Exception):
    """A store could not be reached or refused the operation."""


def dsn() -> str | None:
    value = os.environ.get(DSN_ENV, "").strip()
    return value or None


def enabled() -> bool:
    return dsn() is not None


def pool():
    global _pool
    with _lock:
        if _pool is None:
            value = dsn()
            if value is None:
                raise StoreError(f"{DSN_ENV} is not set")
            from psycopg_pool import ConnectionPool
            _pool = ConnectionPool(value, min_size=1, max_size=8, open=True,
                                   timeout=10, kwargs={"autocommit": True})
        return _pool


def close() -> None:
    global _pool
    with _lock:
        if _pool is not None:
            _pool.close()
            _pool = None
```

**Interfaces:**
- Consumes: `pipeline.pgstore.pool()`, `pgstore.StoreError`.
- Produces: `CredentialStore(path=None, keys=None, dsn=None, ...)`; `cred.StoreError` (re-export of `pgstore.StoreError`, and DuckDB errors are wrapped into it); `default_store()` picks Postgres when `pgstore.enabled()`.

Approach: introduce a tiny `_Backend` protocol inside `credentials.py`:

```python
class _Backend:
    def execute(self, sql: str, params: tuple = ()) -> list[tuple]: ...
    def after_delete(self) -> None: ...      # DuckDB: _flush + _compact; Postgres: no-op
    def after_write(self) -> None: ...       # DuckDB: _flush; Postgres: no-op
```

- `_DuckBackend(path)`: wraps today's `_connect(path)`; `execute` runs `conn.execute(sql, params).fetchall()`; `after_*` call the existing `_flush`/`_compact`. `?` placeholders stay.
- `_PgBackend()`: `with pgstore.pool().connection() as c: return c.execute(sql.replace("?", "%s"), params).fetchall()`; schema created once per process with `CREATE TABLE IF NOT EXISTS` using `TIMESTAMPTZ` columns; every `psycopg.Error` re-raised as `StoreError`.
- `CredentialStore.__init__(..., dsn=None)`: `self.backend = _PgBackend() if (dsn or (path is None and pgstore.enabled())) else _DuckBackend(self.path)`. `self.path` stays for the DuckDB case so the raw-bytes tests keep working.
- Every method: replace `conn = self._conn()` + `conn.execute(...)` with `self.backend.execute(...)`; replace `_flush(conn, self.path)` with `self.backend.after_write()` and `_compact(self.path)` with `self.backend.after_delete()`.
- The three SQL statements that use DuckDB-only syntax must be checked: `INSERT ... ON CONFLICT` is fine in both; `now()` comparisons must pass Python datetimes as params (already the case via `_utc`).
- `StoreError = pgstore.StoreError`; `_DuckBackend.execute` wraps `duckdb.Error` into `StoreError` so `api/custody.py` catches one type. Keep `CustodyUnavailable` as-is (it is the "no key" refusal).
